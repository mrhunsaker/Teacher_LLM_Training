# Self-Directed Practice Guide — Sessions 1–6

This guide supports independent completion of the first six sessions in the ten-session course. It is designed for individual completion; discussion with colleagues is optional, not required. You may complete each session in one sitting or divide it into shorter study blocks. The [AI Literacy Self-Study Guide](ai-literacy-self-study-guide.md) covers Sessions 7–10; the [Course Map and Assessment Plan](course-map-and-assessment-plan.md) is the definitive source for sequence and assessment timing.

The course is designed for special education professionals—including special and general education teachers, TVIs, teachers of deaf and hard-of-hearing students, school psychologists, SLPs, and related-service colleagues—with varied AI experience. Select one fictional case aligned with your role and scope of practice. No programming is required.

## How to complete each session

1. Read the named module and the relevant section of your selected fictional case.
2. Work through the practice task using only fictional or synthetic information.
3. Save the artifact listed for that session.
4. Use the evidence checklist to review your work. Revise any item that does not meet the stated standard.
5. Record one question or limitation to revisit. Do not use AI output as a substitute for professional judgment.

Use an LLM only as a bounded drafting, questioning, and analysis partner. It does not replace student assessment, educator judgment, IEP-team decisions, or professional responsibility.

## Course purpose and learning outcomes

By completing Sessions 1–6, you will practice how to:

1. Construct a bounded prompt with a task, context, constraints, output format, and stop condition.
2. Separate known facts, hypotheses, and unknowns before planning.
3. Draft candidate educational or related-service targets for qualified professional review.
4. Build observable task analyses and aligned data tools.
5. Verify model interpretations against raw data, task conditions, and learner perspective.
6. Produce a human-reviewed action report from simulated email.
7. Document iterative Plan → Refine → Build → Refine work.

## Session 1: Bounded prompting

**Estimated time:** 75–90 minutes.

**Read:** [Module 1 — Prompting](01-prompting.md) and the [Reusable Prompt Library](prompt-library.md).

**Complete:**
- Identify one low-risk, role-relevant task.
- Write a broad initial prompt, then revise it to specify one task, relevant context, explicit limits, an accessible output format, and a stop condition.
- Test or mentally simulate the revised prompt with fictional information.
- Annotate facts, assumptions, and unknowns in the output.

**Save:** One bounded prompt, its revision, and a note identifying decisions the model must not make.

**Self-check:** The prompt has one task; uses no real student information; distinguishes facts from unknowns; requests a usable output format; and explicitly prohibits diagnosis, eligibility, placement, service, or IEP-team decisions.

## Session 2: Plan, Refine, and goal brainstorming

**Estimated time:** 75–90 minutes.

**Read:** [Module 2 — IEP-Related Goal Brainstorming](02-iep-goals.md) and your selected case.

**Complete:**
- Create a facts / hypotheses / unknowns table from the case.
- Write a Plan prompt that asks for a neutral task statement and missing evidence.
- Write a Refine prompt that surfaces alternative explanations and questions for the learner and team.
- Select one meaningful task and identify what must be observed.
- Draft up to three candidate target statements or outcome descriptions for professional review. Mark missing information and decisions reserved to qualified professionals and the authorized team.

**Save:** A planning brief and candidate target options, with unknowns and reserved decisions clearly marked.

**Self-check:** No functional performance, communication, literacy, behavior, motivation, or independence is inferred from diagnosis, eligibility, test scores, acuity, grades, or device ownership alone.

## Session 3: Data collection and operational measurement

**Estimated time:** 75–90 minutes.

**Read:** [Module 3 — Building Aligned Data-Collection Tools](03-data-collection.md).

**Complete:**
- Convert the selected target or service outcome into an operational definition.
- Specify conditions, valid opportunities, prompt/support levels, and scoring rules.
- Build a data-collection tool matched to the selected discipline and task.
- Review whether another qualified observer could apply the definitions consistently.

**Save:** An operational definition, aligned data-collection tool, and a brief quality-review note.

**Self-check:** The measure fits the intended skill or outcome, distinguishes independent and supported performance where relevant, and records conditions. Greater than 90% across three sessions is a configurable training convention, not a universal standard.

## Session 4: Excel progress monitoring

**Estimated time:** 75–90 minutes.

**Read:** [Module 4 — Excel Progress Monitoring](04-excel-monitoring.md).

**Complete:**
- Open one synthetic dataset and your data tool from Session 3.
- Enter the synthetic session data.
- Verify denominators, prompt levels, formulas, and at least two calculations manually.
- Describe the graph and values in text.
- Identify one data-quality limitation and explain how it affects interpretation.

**Save:** A completed spreadsheet tracker and a written data summary with verification notes.

**Self-check:** The record documents valid opportunities, prompt levels, accommodations, conditions, and missing data. Do not treat a spreadsheet flag or chart as an instructional decision.

## Session 5: Interpret and refine

**Estimated time:** 75–90 minutes.

**Read:** [Module 5 — Interpreting Progress, Growth, and Possible Plateaus](05-data-based-decisions.md).

**Complete:**
- Select one synthetic dataset.
- Describe level, trend, and variability without claiming a cause.
- Ask the model for competing explanations, then check each against the raw rows and known conditions.
- Identify one testable next step and the evidence needed to review it.

**Save:** A verified interpretation, limitations, possible explanations, and review plan.

**Self-check:** No causal claim is made from a small dataset. Do not change instruction solely because a model recommends it.

## Session 6: Copilot workflow and applied-course consolidation

**Estimated time:** 75–90 minutes.

**Read:** [Module 6 — Microsoft Copilot Morning Email Triage](06-copilot-email.md) and the simulated email lab.

**Complete:**
- Use only the fictional messages supplied in the course.
- Produce an action report that identifies the source message, action, verified date or deadline, uncertainty, and next step.
- Check every proposed action against the original message.
- Reflect on one workflow to retain and one boundary to maintain in Sessions 7–10.

**Save:** A verified advisory action report and applied-course reflection.

**Self-check:** Unknown dates remain explicitly unknown; urgency is explained; source context is retained; and no email is sent, deleted, archived, or committed to autonomously.

## Independent review notes

Use these checks as you work:

- **Facts** are explicitly provided. **Unknowns** are not supplied. **Hypotheses** are plausible explanations that require investigation.
- Acuity, diagnosis, and grades do not establish functional vision, access efficiency, literacy medium, or instructional need.
- A target should define observable behavior, conditions, independence or prompt level, measurement, and an individualized criterion.
- A possible plateau describes a pattern, not its cause. Consider too few observations, inconsistent opportunities, task difficulty, prompt drift, environment, fatigue, attendance, instructional fidelity, and measurement reliability.
- Sender role is one cue in email triage; urgency should depend on verified deadline, impact, and time sensitivity.
- When the model invents a fact, identify which input supports the claim and how the workflow should prevent the error.

## Competency self-review

Use the item-level [Practical Competency Checklist](practical-competency-checklist.md) for self-review and optional peer discussion. Rate each behavior 0, 1, 2, or N/O and record concrete evidence. Do not create a second competency scale from this guide. The independent capstone in Session 10 uses its own 0–3 domain rubric; keep that score separate from the checklist and written assessments.

## Evidence portfolio

Retain:

1. One bounded prompt and revision.
2. One planning brief separating facts, hypotheses, and unknowns.
3. Candidate target language and professional-review questions.
4. One task analysis or instructional artifact.
5. One data-collection plan defining independent and prompted performance.
6. One synthetic data interpretation with verified calculations.
7. One documented refinement and review plan.
8. One simulated email action report with source verification.
9. A reflection describing a model error, limitation, or uncertainty and how you handled it.

This portfolio documents course learning. It is not a professional credential or district evaluation standard. Use applicable district approval, supervision, and team procedures before applying any workflow to real practice.
