# Facilitator and Practice Edition

This chapter turns the existing mdBook into a six-session professional-learning course. It is designed for TVIs, classroom teachers, and related-service colleagues with varied AI experience. No programming is required.

## Course purpose

Participants learn to use an LLM as a bounded drafting, questioning, and analysis partner. The model does not replace student assessment, educator judgment, IEP-team decisions, or professional responsibility.

## Recommended delivery

Six sessions of 75–90 minutes. The sequence can be delivered as six PLC meetings, a two-day workshop, or self-paced study. Use fictional profiles and synthetic data for all practice.

## Course outcomes

Participants will be able to:

1. Construct a bounded prompt with role, task, context, constraints, output, and stop condition.
2. Separate known facts, hypotheses, and unknowns before planning instruction.
3. Draft and professionally review an individualized ECC instructional target.
4. Build observable task analyses and aligned TVI/classroom data tools.
5. Verify a model's interpretation against raw data, conditions, and student perspective.
6. Produce a human-reviewed action report from simulated email.
7. Document iterative Plan → Refine → Build → Refine work.

## Materials

- Existing course chapters and final ECC workbook.
- District-approved LLM access, or the offline peer-review alternative.
- Fictional student cases and synthetic datasets in this edition.
- Spreadsheet software for data practice.
- Keyboard and screen-reader access technology used by participants.

Do not require participants to connect personal or district email accounts. The email lab uses simulated messages.

## Lesson 1: Bounded prompting

**Objectives:** Identify task, context, constraints, output, and stop condition; revise a broad prompt; detect unsupported claims.

**Preparation:** Read Module 1 and the Prompt Library. Prepare one generic ECC task.

**75–90 minute agenda:**
- 0–10: Identify current AI use and one risk.
- 10–25: Demonstrate a broad prompt and bounded revision.
- 25–45: Pairs revise weak prompts: "Make an ECC plan"; "Write a braille goal"; "Analyze this data"; "Choose technology."
- 45–65: Run or simulate one prompt; annotate facts, assumptions, and unknowns.
- 65–80: Peer review using the prompt checklist.
- 80–90: Exit ticket: name one boundary to add to future prompts.

**Artifact:** One bounded prompt and a note identifying decisions the model must not make.

**Evidence:** The prompt has one task, relevant context, explicit limits, an accessible output format, and a stop condition.

## Lesson 2: Plan and Refine

**Objectives:** Separate facts, hypotheses, and unknowns; use an LLM to surface questions; narrow an instructional problem to an observable task.

**Preparation:** Use Maya or a case from the practice-case chapter.

**Agenda:**
- 0–10: Review the educator-led design cycle.
- 10–25: Demonstrate a facts / hypotheses / unknowns analysis.
- 25–45: Participants write a Plan prompt.
- 45–65: Participants write a Refine prompt requesting missing observations and competing explanations.
- 65–80: Select one meaningful task and define needed evidence.
- 80–90: Exit ticket: what question remains and who can answer it?

**Artifact:** Planning brief containing strengths, known facts, unknowns, task, setting, and student-perspective questions.

**Evidence:** No inference about functional vision, literacy medium, motivation, or independence is made from diagnosis, acuity, grades, or device ownership alone.

## Lesson 3: Goal development and measurement

**Objectives:** Define an observable target; specify conditions, opportunities, prompt definitions, and measurement; review candidate goal language.

**Preparation:** Read Modules 2–3 and use fictional baseline data.

**Agenda:**
- 0–15: Demonstrate a broad aspiration versus measurable target.
- 15–30: Define behavior, conditions, opportunities, prompt levels, and data method.
- 30–50: Use the goal prompt to brainstorm up to three options.
- 50–70: Peer review and revise one option.
- 70–85: Discuss why criteria must be individualized.
- 85–90: Exit ticket: what would make the measure invalid in another setting?

**Artifact:** Draft target, operational definition, measurement plan, and professional review notes.

**Evidence:** The target is observable and measurable. Greater than 90% on at least three sessions is treated as a configurable practice example, not a universal standard.

## Lesson 4: Build data tools and monitor progress

**Objectives:** Create a task analysis; align data fields to the target; distinguish independent and prompted performance; verify calculations.

**Preparation:** Read Modules 3–4. Open one synthetic dataset.

**Agenda:**
- 0–15: Demonstrate an operational definition.
- 15–35: Build a task analysis and paired TVI/classroom collection plan.
- 35–55: Calculate at least two synthetic data rows manually.
- 55–70: Describe the graph and values in text.
- 70–85: Identify a data-quality issue and its impact.
- 85–90: Exit ticket: what else is needed before comparing sessions?

**Artifact:** Task analysis, data fields, and written data summary.

**Evidence:** The plan documents valid opportunities, prompt levels, accommodations, conditions, and missing data.

## Lesson 5: Interpret and refine

**Objectives:** Separate description from explanation; identify trend and variability; generate a testable next step.

**Preparation:** Read Module 5 and select one of the three datasets.

**Agenda:**
- 0–15: Demonstrate cautious data description.
- 15–35: Groups inspect improving, variable, or possible-plateau data.
- 35–50: Ask the model for competing explanations.
- 50–65: Verify arithmetic and claims against raw rows.
- 65–80: Select one testable next step and evidence to review.
- 80–90: Exit ticket: what evidence would disconfirm your explanation?

**Artifact:** Verified interpretation, limitations, possible explanations, and review plan.

**Evidence:** No causal claim is made from a small dataset; instruction is not changed solely because a model recommends it.

## Lesson 6: Copilot workflow and capstone

**Objectives:** Extract tasks and dates from simulated email; assign transparent urgency; assemble the evidence portfolio.

**Preparation:** Read Module 6 and the simulated email lab.

**Agenda:**
- 0–15: Demonstrate email triage using fictional messages.
- 15–35: Participants produce an action report and verify sources.
- 35–45: Discuss uncertainty, urgency, and importance.
- 45–75: Assemble the capstone portfolio.
- 75–85: Peer review using the rubric.
- 85–90: Exit ticket: what district approval is needed before real-world use?

**Artifact:** Verified action report and portfolio.

**Evidence:** The report labels unknown dates, explains urgency, retains source context, and takes no autonomous email action.

## Instructor notes and expected answers

- **Facts** are explicitly provided. **Unknowns** are not supplied. **Hypotheses** are plausible explanations requiring investigation.
- Acuity, diagnosis, and grades do not establish functional vision, access efficiency, literacy medium, or instructional need.
- A target should define observable behavior, conditions, independence or prompt level, measurement, and an individualized criterion.
- A possible plateau describes a pattern, not its cause. Consider too few observations, inconsistent opportunities, task difficulty, prompt drift, environment, fatigue, attendance, instructional fidelity, and measurement reliability.
- Sender role is one cue in email triage; urgency should depend on verified deadline, impact, and time sensitivity.
- When the model invents a fact, ask which input supports the claim and how the workflow should prevent it.

## Competency rubric

Use the levels Beginning, Developing, Proficient, and Advanced. Score each area and provide evidence-based feedback.

| Competency | Beginning | Developing | Proficient | Advanced |
|---|---|---|---|---|
| Prompting | Broad, unclear task | Task and context present | Task, scope, constraints, output, stop condition clear | Also requests uncertainty and verification |
| Privacy | Identifiers or excess detail | Removes direct identifiers | Uses approved tool and minimizes data | Recognizes re-identification risk |
| Student analysis | Assumptions treated as facts | Some distinctions made | Facts, hypotheses, unknowns separated; student voice included | Identifies missing perspectives |
| Goal/measurement | Vague target | Partially measurable | Observable, measurable, individualized | Anticipates validity and generalization |
| Data tools | Misaligned fields | Partial alignment | Operational definitions and fields align | Supports consistent cross-setting collection |
| Data interpretation | Accepts model conclusion | Checks some values | Verifies calculations and states limits | Tests competing explanations |
| Iteration | One-shot output | Revises wording only | Uses all four stages with testing | Documents rationale and outcome review |
| Professional judgment | Defers to AI | Inconsistent review | Educator/team retains decision authority | Rejects unsupported output and explains why |
| Email triage | Acts on unverified summary | Checks some messages | Verifies source and deadlines | Explains uncertainty and priority rationale |

## Final evidence portfolio

Participants submit or present:

1. One bounded prompt and revision.
2. One planning brief separating facts, hypotheses, and unknowns.
3. One draft target and professional review notes.
4. One task analysis or instructional artifact.
5. One data-collection plan defining independent and prompted performance.
6. One synthetic data interpretation with verified calculations.
7. One documented instructional refinement and review plan.
8. One simulated email action report with source verification.
9. A reflection describing a model error, limitation, or uncertainty and how it was handled.

Suggested course completion: average score of Proficient across competencies, with no score below Developing for privacy or professional judgment. This is a course-design suggestion, not a professional credential or district evaluation standard.
